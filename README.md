# MedCheck AI

A full-stack demo that detects **potential contradictions** across a patient's medical
records — allergy, medication, diagnosis, and demographic conflicts — and puts them in
front of a clinician for review, with every decision written to an audit log.

> **All data is synthetic.** Patients, documents, and clinical text are generated by the
> seed script. Findings are algorithmic *potential inconsistencies*, not diagnoses. Nothing
> here should be used for real patient care.

## What it does

- **Contradiction detection** — deterministic rules compare statements across a patient's
  documents (e.g. "No known drug allergies" in one note vs. "penicillin allergy with
  hives" in another) and raise a finding with both source excerpts quoted side by side.
- **Document ingestion** — upload a PDF/PNG/JPG; text is extracted (pypdf, OCR if
  configured) and analysis runs automatically. Extraction failures are reported honestly,
  never faked.
- **Clinician review workflow** — doctors verify, dismiss, or escalate a finding with a
  mandatory reason. Source documents are never modified.
- **Roles & audit trail** — doctor / records-staff / patient / admin, enforced
  server-side. Every login, upload, review, and admin action is recorded in an audit log.

## Run it (PowerShell)

Two terminals: one for the API, one for the UI.

### 1. Backend — `http://127.0.0.1:8001`

```powershell
cd backend
py -m venv .venv
.venv\Scripts\Activate.ps1
pip install -r requirements.txt
uvicorn app.main:app --host 127.0.0.1 --port 8001 --reload
```

On first boot the database is created and seeded with 21 synthetic patients, the demo
patient's 6-visit history, 5 documents with deliberate conflicts, and the resulting
findings. Health check: <http://127.0.0.1:8001/api/health> (interactive docs at `/docs`).

> **Port note:** the backend uses **8001** — port 8000 was blocked by a Windows permission
> error. If you change it, update `frontend/.env` to match.

### 2. Frontend — `http://localhost:5173`

```powershell
cd frontend
npm install
npm run dev
```

Open <http://localhost:5173>. The dev server must run on Vite's default port **5173** —
that is the origin the backend's CORS allowlist permits. The API base URL is read from
`frontend/.env` (defaults to `http://127.0.0.1:8001`).

### 3. Sign in with a seeded account

| Username   | Password      | Role    |
|------------|---------------|---------|
| `doctor1`  | `Doctor123!`  | doctor  |
| `records1` | `Records123!` | records staff |
| `patient1` | `Patient123!` | patient (linked to MC-001) |

Administrator accounts cannot be self-registered. In development, create the first one
with `POST /api/auth/dev-bootstrap-admin`, or register a normal account and approve it
from the admin **Users** page.

## Run the tests

```powershell
cd backend
.venv\Scripts\Activate.ps1
pytest
```

Covers health, auth, patient CRUD, document upload, findings/review workflow,
contradiction rules, and cross-user data isolation.

## Configuration

All optional; safe defaults for local dev (see `backend/app/config.py`):

| Env var | Purpose |
|---------|---------|
| `MEDCHECK_DATABASE_URL` | DB URL — SQLite by default, set a `postgresql://` URL to migrate |
| `MEDCHECK_SECRET_KEY` | JWT signing key — **dev default is insecure; override for any shared deploy** |
| `MEDCHECK_ALLOWED_ORIGINS` | Comma-separated CORS origins (default `http://localhost:5173`) |
| `MEDCHECK_UPLOAD_DIR` | Where uploaded files are stored |
| `MEDCHECK_MAX_UPLOAD_BYTES` | Upload size limit (default 10 MB) |

Frontend:

| Env var | Purpose |
|---------|---------|
| `VITE_API_BASE_URL` | Backend base URL (default `http://127.0.0.1:8001`) |

## Optional OCR

Scanned PDFs and images need the Tesseract engine plus the Python bindings:

```powershell
winget install -e --id UB-Mannheim.TesseractOCR
pip install pytesseract pillow
```

Without OCR, uploads still work — image/scanned extraction is reported as
`ocr_unavailable` rather than silently succeeding.
